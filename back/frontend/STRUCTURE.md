# Как добавлять код в админку, чтобы файл не вырос в 1000 строк

Коротко: **делить сразу, а не потом**. Разбивать «потом» почти никогда не случается — так и получается
один `GoodPage.jsx` на 750 строк, где состояние, загрузка фото, подтверждения и разметка вперемешку.

Живой пример, на который можно смотреть: [`src/features/goods`](src/features/goods/README.md).

## 1. Сначала реши, на какую «полку» кладёшь код

| Полка | Что туда | Признак |
|---|---|---|
| `features/<фича>/ui/` | маленький элемент, который может понадобиться в другом месте | принимает `value` + `onChange`, ничего не знает про товар (пример: `PhotoTile`, `PriceInput`, `StockStepper`) |
| `features/<фича>/components/` | блок страницы (секция) | один блок = один файл = один смысловой заголовок (`VariantsSection`, `NotesSection`) |
| `features/<фича>/model/` | логика и состояние | чистые функции (`formState.js`), правила (`snapshot.js`), хук (`useGoodForm.js`) |
| `features/<фича>/<Page>.jsx` | сборка страницы | только: данные из хука → секции → `confirm`/`navigate`/API |
| `features/<фича>/constants.js` | справочники, моки, лимиты | то, что не меняется во время работы |
| `shared/components/` | то, что нужно **разным фичам** | `PageButton`, `AccessControl` |

Новая страница → новая папка `features/<имя>/` с теми же подпапками. Не складывай всё в
`features/dashboard/components/`: это должна быть папка роутера, а не свалка страниц.

## 2. Три вопроса перед тем, как писать

1. **Это разметка или логика?** Если логика — она идёт в `model/`, а не в JSX.
2. **Это нужно где-то ещё?** Да → `ui/` (или `shared/`). Нет → оставляй внутри своей секции.
3. **Это состояние или вычисление?** Состояние — `useState` в хуке; вычисление — чистая функция в `model/`.

## 3. Красные флаги — пора делить

- файл больше **250–300 строк** (линтер уже предупреждает: `max-lines` в `eslint.config.js`);
- больше **7 пропсов** у компонента или больше **7 `useState`** в одном компоненте;
- один и тот же кусок JSX **скопирован 3 раза** → это `ui`-компонент (`PhotoTile` вместо трёх копий плитки);
- больше **2 `useEffect`** в компоненте — почти всегда один из них лишний;
- в компоненте появились «хелперы» и расчёты между состояниями → в `model/`;
- `className` на 5+ строк с тернарниками — вынеси в отдельный компонент или в объект стилей.

## 4. Приёмы, которые можно повторять

- **Значение + колбэк.** Секции «глупые»: получают `value` и `onChange`, сами ничего не хранят
  и не знают про `setState` формы.
- **Локальное состояние — в блоке.** Открыт список категорий, развёрнуты заметки, какое фото открыто
  в лайтбоксе — это дело блока, а не страницы.
- **`key` вместо синхронизации.** Нужно «обнулить» форму при смене товара — перемонтируй компонент
  (`<GoodForm key={id}/>`), а не пиши `useEffect`, который дёргает `setState`.
- **«Связи с миром» — на странице.** `window.confirm`, `navigate`, запросы к API живут в `GoodPage.jsx`,
  а не внутри секции: так секцию можно менять и тестировать отдельно.
- **Модель без React.** Функции из `model/` — обычные «было состояние → стало состояние»,
  их легко покрыть тестами.

Скелет новой секции:

```jsx
export function DiscountSection({discount, onDiscountChange}) {
    return (
        <div className="flex flex-col gap-3 rounded-xl border border-zinc-200 bg-white p-4">
            <span className="text-xs font-semibold uppercase text-zinc-500">Скидка</span>
            <PriceInput value={discount} onChange={onDiscountChange} inputClassName="w-28"/>
        </div>
    );
}
```

## 5. Пример: добавить новое поле товара (4 шага)

1. Если есть справочник или лимит — в `constants.js`.
2. Поле в состояние и в слепок: `model/formState.js` + `model/snapshot.js`
   (иначе «Сохранить» не заметит изменение).
3. Отрисовать в подходящей секции, забрав `value` и `onChange` из хука.
4. Если поле — новый смысловой блок: новая секция в `components/` + строчка в `GoodPage.jsx`.

## 6. Пример: новая страница

1. `features/<имя>/{components,model,ui}`, `constants.js`, `<Имя>Page.jsx`.
2. Маршрут в `src/index.jsx`.
3. `README.md` в папке фичи: структура + что не доделано (как в `features/goods`).
4. Если что-то из `models`/`shared` дублируется со страницей товара — вынеси в `shared/`.

## 7. Перед коммитом

- `npm run lint` — 0 ошибок; предупреждения `max-lines` не игнорируй, это список на разбор;
- `npm run build`;
- пройти руками основной сценарий: изменил → «Сохранить» → индикатор «Изменений нет».

## 8. Про сам линтер

В `eslint.config.js` включено правило-напоминалка:

```js
'max-lines': ['warn', {max: 300, skipBlankLines: true, skipComments: true}],
```

Оно ничего не ломает (это warning, а не error), но подсвечивает файлы, которые пора делить.
Порог можно подкрутить: маленькие файлы — норма, 300 строк — уже сигнал.

Сейчас предупреждают два «исторических» файла (их стоит разобрать по тому же принципу,
список должен только сокращаться):

- `src/table/tableInfo.jsx` (666)
- `src/addForm/addFormReport.jsx` (471)

## 9. Как разобрать файл-свалку (живой пример: бывший `shared/components/Ui.jsx`)

`Ui.jsx` был на 696 строк, и в нём лежали **четыре разные вещи**. Разбор занял 6 шагов:

1. **Выписать, что внутри** (по экспортам и данным):
   мок `goods` на 225 строк · `AsideButton` · `PageButton` ·
   `SortByStatusButtons` · `SearchByName` · `TableRender`.
2. **Задать каждому куску вопрос «кто владелец?»**:
   данные → моки фичи; навигация сайдбара → дашборд; кнопка → общий примитив;
   фильтр/поиск/таблица товаров → фича товаров.
3. **Примитивы — в `shared/`**, но только те, что нужны 2+ фичам:
   `PageButton` уехал в `shared/components/PageButton.jsx`, `AsideButton` — в
   `features/dashboard/components/AsideButton.jsx` (нужен только сайдбару).
4. **Данные — в `mocks/`**, отдельно от разметки: 20 товаров переехали в
   `features/goods/mocks/goodsList.js`.
5. **Логику — в хук/чистые функции**: фильтр, пагинация и счётчики →
   `features/goods/model/goodsTable.js`; состояние страницы и выделения →
   `features/goods/model/useGoodsTable.js`.
6. **Большой JSX — по визуальным секциям**: `TableRender` (320 строк) распался на
   `GoodsTable` (склейка) + `GoodsTableHeader` + `GoodsTableRow` + `GoodsPagination`
   + `GoodsSelectionBar`.

Было: `Ui.jsx` 696 строк, из которых «UI» — меньше трети.

Стало: 1 общий примитив (`shared/components/PageButton.jsx`, 52 строки),
1 элемент дашборда, мок, 2 файла логики и 6 компонентов списка —
самый большой из них 53 строки.
